# v2.11.0 Slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, single session; the machine allows no parallel subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove what this fork adds on top of upstream: provenance, a fixture-driven Anthropic conformance suite against a local mock upstream, resilience (backoff/jitter/retry-after/timeouts/shutdown), hardening (limits, header allow-list, redaction, security headers, health/metrics) and a typed, linted, coverage-gated, CodeQL-clean CI.

**Architecture:** New behaviour lives in small, pure, `// @ts-check` modules under `src/resilience/` and `src/http/`, each unit-tested, then wired into the existing `server.js` / `cloudcode-client.js` / `index.js` with minimal edits. The conformance suite spawns the real proxy against a scripted mock Cloud Code server and replays JSON fixtures from `test/fixtures/`.

**Tech Stack:** Node 20/22 ESM, Express 4, `node:test`, c8, TypeScript (`tsc --noEmit` over JSDoc), ESLint 9, Prettier 3, express-rate-limit, GitHub Actions (CodeQL, gitleaks, Dependabot).

**Spec:** the frozen v2.11.0 task, Definition-of-Done items 1-5 (recorded in `TASKS.md`).

## Global Constraints

- No real Google/Antigravity credentials anywhere; fixtures are synthetic JSON under `test/fixtures`.
- Node 20 + 22 matrix; coverage gate >= 80% (c8) over the gated module set; `tsc --noEmit`, eslint, prettier check all green.
- CodeQL on the PR must have 0 open alerts; `npm audit --omit=dev` clean or justified.
- Never write environment URLs/hosts/tokens into the repo. Commit identity unchanged; push only via push.sh.
- Run node tests one process at a time; never watch mode.

## Review Focus

- Malformed JSON body / wrong content-type -> Anthropic-shaped 400, never Express' HTML error page (validation task test).
- Body above the limit -> 413 `request_too_large` JSON (validation task test).
- Upstream 429 with `Retry-After` on every account -> client gets a `retry-after` header (conformance fixture `error-429-retry-after`).
- Upstream hang -> request ends with 504 `timeout_error` within the timeout, not a hung socket (conformance fixture `error-timeout`).
- Secrets in client headers or upstream error bodies never appear in logs (redaction e2e test).
